# LLM-баги и фиксы — Psy Family chatbot

Журнал всех проблем, обнаруженных при тестировании, и применённых решений.
Покрывает: 21 кейс ручного тестирования, 47 integration tests, 87 QA-проверок, 6 eval-сценариев.

---

## Критические баги

### 1. Бот записывает без сбора данных
**Кейсы:** case12, case15 | **Тесты:** C3/C4, S6, Case25full, S18f, S18g

Бот подтверждал запись без запроса имени и даты рождения.

**Причина:** LLM классифицировал "Да, записывайте" как завершение записи.
**Фикс:** Жёсткая проверка в коде: запись завершается ТОЛЬКО при наличии `patient_name` (2+ слова) И `birth_date`. Flow: confirm_slot → ask_patient_name → ask_birth_date → complete.
**Файл:** `ai_agent/nodes/appointment.py`

### 2. Бот раскрывает что он ИИ
**Кейсы:** case5 | **Тесты:** F2, S4_step3, S4_step4

На "Где ты живешь?" ответил: "Я — большая языковая модель, разработанная компанией Google".

**Причина:** Модель игнорирует system prompt и отвечает дефолтом.
**Фикс:** Железное правило в ALICE_PERSONA + template-ответ для off-topic (не LLM). Keyword-проверка: Google, OpenAI, Anthropic, "языковая модель".
**Файл:** `ai_agent/utils/prompts.py`, `ai_agent/nodes/fallback.py`

### 3. Бот записывает соседей/друзей
**Кейсы:** — | **Тесты:** Neighbor checklist

"Хочу записать соседа к врачу" → бот начинал запись без проверки.

**Причина:** Бизнес-правило было только в промпте, LLM его игнорировал.
**Фикс:** Keyword-check в коде: "сосед", "друг", "коллег" → отказ + номер клиники.
**Файлы:** `ai_agent/nodes/appointment.py`, `ai_agent/nodes/doctor_info.py`

## Потеря контекста

### 4. Бот сбрасывает контекст на "Ок"/"Хорошо"
**Кейсы:** case2, case3 | **Тесты:** E1, S2_step2

После предложения врача, "Ок" → "Здравствуйте! Чем могу помочь?"

**Причина:** LLM классифицирует "Ок" как greeting/arbitrary_message.
**Фикс:** Router: если prev_intent=want_procedure и есть pending_doctor → "Ок"=согласие → предлагает слот. Greeting = template.
**Файл:** `ai_agent/nodes/router.py`

### 5. Бот игнорирует вопросы при сборе данных
**Кейсы:** case11, case14 | **Тесты:** S2_step3, E2/E3, Case47c

Бот спросил имя, пользователь спрашивает про стаж → бот игнорирует и снова просит имя.

**Причина:** Router при pending_action маршрутизировал всё в appointment.
**Фикс:** Router: question_about_doctor/question_about_clinic → соответствующий handler. `_booking_cta`: после ответа дописывает напоминание о данных.
**Файлы:** `ai_agent/nodes/router.py`, `ai_agent/agent.py`

### 6. Бот теряет контекст при упоминании болезни во время записи
**Кейсы:** case21 (частично) | **Тесты:** Case47a, Case47b

Бот ждёт имя, "У меня невротическое расстройство" → бросает запись, начинает подбор врача с нуля.

**Причина:** Router видит intent=want_procedure и перенаправляет в doctor_info.
**Фикс:** Router проверяет лечит ли текущий врач эту болезнь → подтверждает и продолжает сбор: "Да, врач занимается лечением таких состояний. Как вас зовут?"
**Файлы:** `ai_agent/nodes/router.py`, `ai_agent/nodes/appointment.py`

### 7. "На какую дату?" → бот спрашивает "Что вас беспокоит?"
**Кейсы:** case18 | **Тесты:** 3.6

Пользователь спрашивает про даты — бот теряет контекст врача и начинает сначала.

**Причина:** LLM классифицирует как arbitrary_message, fallback не знает про врача.
**Фикс:** Router: если prev_intent=want_procedure/question_about_doctor и есть pending_doctor → предлагает слот.
**Файл:** `ai_agent/nodes/router.py`

### 8. Подтверждение слота + вопрос → бот переспрашивает слот
**Кейсы:** case19 | **Тесты:** Case44, S3_step3

"Да, подходит. Расскажите про врача" → бот заново спрашивает дату/время.

**Причина:** Router при confirm_slot не обрабатывал multi-intent (chosen_slot + question).
**Фикс:** Router: если intent=chosen_slot и secondary=question_about_doctor → принимает слот, меняет pending на ask_patient_name, маршрутизирует в doctor_info.
**Файл:** `ai_agent/nodes/router.py`

## Составные сообщения

### 9. Бот отвечает только на один вопрос из составного
**Кейсы:** — | **Тесты:** S3 (все шаги), Scenario 4 (все 8 шагов), Case44

"Хочу записаться и расскажите про врача" → только слот, без информации о враче.

**Причина:** Pipeline extract→route обрабатывает один intent.
**Фикс:** `additional_questions` в ExtractedMessage (до 3 допвопросов). Fallback-детекция по "?" и compound-паттернам. После template-ответа → LLM дописывает. Для LLM-stream → допвопросы в промпт.
**Файлы:** `ai_agent/schemas.py`, `ai_agent/utils/prompts.py`, `ai_agent/agent.py`

### 10. additional_questions ложно срабатывает на простых ответах
**Кейсы:** — | **Тесты:** (обнаружен при ручном тестировании)

"Иван Иванов" → бот дописывает описание врача как допвопрос.

**Причина:** LLM extraction тащит additional_questions из предыдущего хода.
**Фикс:** Если pending_action сменился (данные приняты) — additional_questions не обрабатываются. Плюс явные примеры пустого массива в промпте.
**Файлы:** `ai_agent/agent.py`, `ai_agent/utils/prompts.py`

## Качество ответов

### 11. Бот выдаёт список всех врачей
**Кейсы:** — | **Тесты:** B2

"А кто у вас работает?" → перечислил всех 10 врачей.

**Причина:** LLM видит список в system prompt и считает нужным выдать целиком.
**Фикс:** Правило в ALICE_PERSONA: "НИКОГДА не выдавай весь список. Спроси проблему."
**Файл:** `ai_agent/utils/prompts.py`

### 12. Размытый ответ вместо конкретного врача
**Кейсы:** case21 | **Тесты:** 2.5, B2

"Кто лечит невротическое расстройство?" → "У нас опытные специалисты" без имени.

**Причина:** DoctorsService не находил совпадения, fallback давал общий ответ.
**Фикс:** DiseaseMatcher с fuzzy matching (70% порог) + каталог aliases + ранжирование врачей по опыту.
**Файлы:** `ai_agent/services/disease_matcher.py`, `ai_agent/data/diseases.json`

### 13. Бот не предлагает записаться после информации о враче
**Кейсы:** case4, case16 | **Тесты:** 2.3, Case45

Дал информацию о враче — тупик, не предложил записаться.

**Причина:** Нет CTA в конце ответа.
**Фикс:** Правило: каждый ответ заканчивается следующим шагом. `_booking_cta` для booking flow, рандомные CTA для остальных.
**Файлы:** `ai_agent/nodes/doctor_info.py`, `ai_agent/utils/prompts.py`

### 14. Ответ на вопрос о клинике нерелевантен
**Кейсы:** case17 | **Тесты:** 2.2, 3.10, S4_step2

"Как называется клиника?" → "Рекомендуем приехать за 15–20 минут".

**Причина:** LLM при confirm_slot классифицирует вопрос как asks_about_slot.
**Фикс:** Keyword-based fallback: "называется", "клиника", "адрес" → faq.
**Файл:** `ai_agent/nodes/router.py`

### 15. Пустой ответ на "Расскажите про клинику"
**Кейсы:** case7 | **Тесты:** S4_step1, F3

Бот возвращал пустую строку.

**Причина:** FAQ не находил совпадения, fallback не генерировал ответ.
**Фикс:** Fallback для clinic_related: использует full_system_prompt с FAQ для LLM.
**Файлы:** `ai_agent/nodes/faq.py`, `ai_agent/nodes/fallback.py`

### 16. Стоимость: "не располагаю информацией"
**Кейсы:** — | **Тесты:** S17d

Цены есть в doctors.json, но бот говорил что не знает.

**Причина:** Hardcoded "К сожалению..." в doctor_info_node.
**Фикс:** Берёт цену из doctor.cost, добавляет: "Могу перевести к администратору. Записать или перевести?"
**Файл:** `ai_agent/nodes/doctor_info.py`

### 17. Нет свободных слотов — бот молчит
**Кейсы:** case8, case9 | **Тесты:** S5_step1, 1.4, 3.7

"Других слотов нет" и тишина. Нет альтернативы.

**Причина:** Appointment node не предлагал другого врача/обратный звонок.
**Фикс:** `_suggest_similar_doctor()`: ищет врача с похожей специализацией. Если никого — предлагает оставить номер.
**Файл:** `ai_agent/nodes/appointment.py`

### 18. "А зачем дата рождения?" → бот завершает запись
**Кейсы:** case15 | **Тесты:** 1.8, S2_step5, F5

Вместо объяснения — сразу записал без данных.

**Причина:** LLM классифицировал как chosen_slot/arbitrary, appointment завершал flow.
**Фикс:** Appointment fallback: если pending=ask_birth_date и DOB не извлечена → LLM с контекстом "объясни зачем ДР и переспроси". Не завершает запись.
**Файл:** `ai_agent/nodes/appointment.py`

### 19. Избыточная эмоциональность
**Кейсы:** case8 | **Тесты:** G2, 3.8

"Он ОБЯЗАТЕЛЬНО поможет вашему ребенку!" — неуместный тон.

**Причина:** LLM без ограничений добавлял эмоции.
**Фикс:** ALICE_PERSONA: профессиональный тон, 1-3 предложения. DOCTOR_INFO_SUMMARY_PROMPT: только факты.
**Файл:** `ai_agent/utils/prompts.py`

## Технические баги

### 20. Кракозябры (��) в "записываю"
**Кейсы:** case1, case11, case14 | **Тесты:** S1 no_encoding, H1

Encoding artifacts в ответах.

**Причина:** Кодировка при передаче между компонентами.
**Статус:** Не воспроизводится на текущем стеке. Проверяется eval-тестом S1.

### 21. Anti-repeat hint утекает в ответ
**Кейсы:** — | **Тесты:** (обнаружен при ручном тестировании)

Бот выводит: "ВАЖНО: не повторяй свои предыдущие ответы..."

**Причина:** Hint добавлялся как отдельное system-сообщение ПОСЛЕ user message. qwen3-coder эхом возвращает.
**Фикс:** Hint встраивается В основной system prompt (первое system-сообщение).
**Файл:** `ai_agent/agent.py`

### 22. Дублирование CTA при боковых вопросах
**Кейсы:** — | **Тесты:** Case35, E2/E3

"Вам подходит время?\n\nТак что, записываем?" — двойной CTA.

**Причина:** `_cta()` в doctor_info и `_booking_cta` в agent.py оба добавляли CTA.
**Фикс:** `_cta()` проверяет: если `_booking_cta` уже установлен → возвращает "".
**Файл:** `ai_agent/nodes/doctor_info.py`

### 23. LLM говорит от лица врача
**Кейсы:** — | **Тесты:** (обнаружен при eval S3)

"ко мне, Олегу Замильевичу" — в addendum для допвопросов.

**Причина:** LLM addendum не имел инструкции о роли.
**Фикс:** "Говори от лица оператора Алисы, НЕ от лица врача".
**Файл:** `ai_agent/agent.py`

### 24. "А как тебя зовут?" воспринимается как имя пациента
**Кейсы:** case14 | **Тесты:** Case14, Case42

Бот принимал вопрос "Как тебя зовут?" как ФИО пациента.

**Причина:** Extraction извлекала patient_name из вопроса.
**Фикс:** Extraction prompt: "Извлекай ТОЛЬКО когда пациент сообщает СВОЁ имя. 'Как тебя зовут?' — вопрос боту → null". Router: keyword-check на "вас/тебя/ты" + "зовут/имя" → bot-directed question.
**Файлы:** `ai_agent/utils/prompts.py`, `ai_agent/nodes/router.py`

### 25. "Иванов" матчится с отчеством "Иванович"
**Кейсы:** — | **Тесты:** Case29

Пользователь ищет врача "Иванов", fuzzy matching находит Хайретдинова через "Замильевич"→"Иванович".

**Причина:** Fuzzy matching без word-level проверки.
**Фикс:** Stricter word-based matching: сравниваются отдельные слова ФИО, отчество пропускается.
**Файл:** `ai_agent/services/doctors_service.py`

## Общие выводы

1. **Не доверяй LLM для бизнес-логики** — сбор данных, проверка родства, маршрутизация — всё в коде
2. **System prompt ≠ гарантия** — модель может игнорировать, эхом возвращать, интерпретировать по-своему
3. **Template > LLM** для критичных ответов (подтверждение записи, запрос данных)
4. **Extraction ненадёжна** — keyword matching и regex как fallback для ключевых маршрутов
5. **History leaks** — LLM тащит контекст из предыдущих ходов в поля текущего хода
6. **CTA в каждом ответе** — без него пользователь "зависает" в тупике
7. **Eval нужен статистический** — один прогон ничего не значит, нужно N повторов для LLM-нестабильности
